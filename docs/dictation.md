# Local voice dictation (P4)

Goal: Wispr-Flow-style dictation that is offline, free and private. Hold a key (desktop) or tap the mic (phone), speak, and the text lands at the cursor or in the task box.

## What exists now
- `desktop/src/dictation/vad.ts` - trims leading/trailing silence, ignores clicks and coughs.
- `desktop/src/dictation/cleanup.ts` - removes unambiguous fillers (um, uh...), personal dictionary (whole words, longest first, literal replacement), spacing and capitals, Hindi danda.
- `desktop/src/dictation/pipeline.ts` - clip -> VAD -> local `Transcriber` -> cleanup. Audio lives only in memory and is wiped on every path (success, no speech, error, cancel). Errors surface as safe codes only.
- All covered by tests with synthetic audio (`desktop/test/dictation.test.ts`).

## Engine provisioning (built Oct 24)
- `desktop/src/dictation/provision.ts` - first run downloads one pinned whisper.cpp build (`b5454`, ggml-org release) and one pinned model (ggml-tiny, ~75 MB) into the private data directory, verifies both against recorded sha256 hashes before anything runs, extracts with the system `tar` (bsdtar on Windows 10+), and only then registers `dictation.*`. Both entrypoints (CLI and the Electron tray app) wire this; before this change the tray app never constructed an engine at all.
- Platforms: Windows x64 and Linux x64 auto-provision. macOS and other targets report unavailable and point at the manual env override below; nothing is downloaded there.
- `ORBIT_WHISPER_BIN` + `ORBIT_WHISPER_MODEL` always win and skip every download. Provisioning contacts github.com and huggingface.co exactly once per computer; whisper.cpp and the Whisper models are MIT licensed.
- Verified end to end (2026-10-24, Linux sandbox): real downloads passed hash verification, the extracted prebuilt `whisper-cli` transcribed real 16 kHz speech (the standard jfk.wav sample) through `WhisperCpp` and through the full `dictate` pipeline with the correct transcript. Hinglish accuracy still needs real recorded clips; no accuracy claim is made.

## Privacy rules (enforced in code where possible)
- Audio never leaves the paired devices; no cloud engine is a valid `Transcriber`.
- Nothing is stored after transcription; buffers are zeroed.
- A mic indicator is always shown while recording.

## Prior art
OpenWhispr and VoiceFlow are MIT: ideas and architecture only, attribution if any code is ever reused. Nothing has been copied.

## Running it
Desktop (Windows x64 / Linux x64): nothing to set up. On first start the app downloads the pinned engine + model into the private data directory (one time, ~85 MB) and dictation switches on when verification passes; if the download or hash check fails, dictation stays off and the failure is logged (metadata only). To use your own engine or a bigger model, set `ORBIT_WHISPER_BIN` and `ORBIT_WHISPER_MODEL` before start - the override skips all downloads. macOS: install whisper.cpp yourself (e.g. `brew install whisper-cpp`) and set the same two variables.
Android phones record compressed m4a, so the computer also needs ffmpeg: set `ORBIT_FFMPEG` to its path (or have ffmpeg on PATH when using the tray app). iPhones record WAV and do not need it. The compressed clip is decoded from a private temp file - MP4 cannot be demuxed from a pipe - and the file is overwritten and deleted right after each decode.
Audio is only held in memory and zeroed after each clip. The phone shows a Recording indicator while the mic on.
The phone mic button lives on the Tasks screen (tap to record, tap to stop; dictated text lands in the task box); it shows the computer's engine-setup state with explicit Retry/Cancel and never fires a download by itself. Both phone audio formats are verified end to end in-sandbox with the real engine; on-device capture remains real-device pending. A model picker shipped 2026-10-24: Settings offers tiny (75 MB, default), base (142 MB) and small (466 MB), all pinned and sha256-verified from the official whisper.cpp bucket; the picker shows a conservative hardware suggestion (by cores and memory) but the user chooses. Switching to a model that is not downloaded yet runs the same visible, cancellable provisioning path; switching to a downloaded one swaps the engine in place. Env overrides still win.

The desktop dictation hotkey shipped 2026-10-24: a user-chosen global shortcut (default Control+Shift+D, off by default) toggles one recording, and the local engine transcribes it. The transcript is never sent anywhere automatically - it lands in Orbit with Copy and Dismiss, plus, when the platform can verify window identity (Windows via GetForegroundWindow handle + process, X11 via xprop WM_CLASS + active-window id), a confirm-to-insert button naming the captured window; the phone mic flow shows the same confirm ("Also insert into <window>?", Insert / Not now) when the desktop reported a target at recording start. On Linux/X11, insertion is one confirmed action, and it is paste-based: the captured window is activated and its identity re-verified, the transcript replaces the clipboard (a clipboard holding sensitive, image or oversized content is never clobbered - insertion reports clipboard-unavailable), one paste keystroke is sent (Ctrl+Shift+V for known terminals, Ctrl+V for a small allowlist of known GUI text apps, and no keystroke at all for unknown window classes, which report unsupported-target), focus is re-checked after the keystroke, and the previous clipboard is restored after a short delay (on X11 the transcript may be visible to local clipboard readers during that sub-second window). The reported outcome stays honest: 'paste-sent' means the keystroke went to the verified window - not that the app accepted the text - and 'focus-lost' means the paste may have gone elsewhere; there is no automatic retry or resume, since the delivery state is ambiguous at that point. A paste is still one keystroke delivered to whatever the OS has focused at that instant, so it is not a delivery guarantee - only the pre/post focus verification and the allowlist bound the exposure. On Windows the hotkey confirm shows Copy and Dismiss only: the earlier per-character typing path was removed because keystroke delivery into arbitrary apps is not safe by category (command-mode editors, single-key shortcuts, terminal control and newline handling, non-text focused controls) and the wrong-target disclosure risk is independent of paste vs typing. Windows insertion returns when a delivery path is verified on a real PC; the phone insert offer was never shown on Windows. Wayland and macOS have no reliable focus identity, so insert never appears there. Proven in-sandbox (2026-10-25, Xvfb + xfwm4 + xfce4-terminal, real whisper engine and xdotool/xclip): a dictated JFK clip landed byte-exact in the terminal with the prior clipboard restored and the single-use offer consumed; an xmessage target was refused as unsupported with no keystroke sent. The full Electron hotkey flow was additionally click-tested end to end the same day with INJECTED audio (ORBIT_DICTATION_FAKE_CLIP test hook, NOT microphone capture): real global shortcut -> real transcription -> real preview card naming the live-captured allowlisted window -> real mouse click on Insert -> byte-exact text in the terminal, prior clipboard restored; with no allowlisted window focused, the card shows Copy/Dismiss only. A red recording banner and the tray tooltip show while capturing; disabling the shortcut or quitting cancels any recording immediately and releases the mic; every capture error path stops the mic tracks, and captured audio is zeroed after use. The global keypress and the OS-level capture path were additionally verified in-sandbox 2026-10-25 (Xvfb + xfwm4, no INJECTED audio): a real XTEST Ctrl+Shift+D keypress fired the app's real global-shortcut grab (an isolated Electron probe confirmed Control+Shift+D fails to register only because Orbit already holds the grab), the renderer's real getUserMedia captured from a PulseAudio remap source (a virtual microphone fed by a wav loopback - real Chromium/PulseAudio/AudioContext/IPC capture path, not a physical microphone and not the ORBIT_DICTATION_FAKE_CLIP hook), and the real tiny engine transcribed it to the JFK text on the real preview card with Copy/Dismiss (screenshot-verified). A physical microphone, the Windows hotkey, and the phone insert surface remain real-device pending.
