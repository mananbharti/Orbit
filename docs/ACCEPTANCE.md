# Acceptance Matrix

Every feature is at exactly one verification level per platform:

- **Implemented** - code complete on `v1.1`, reviewed.
- **Automated test** - unit/integration tests in CI (desktop tests use synthetic OS adapters unless marked otherwise).
- **Real-device verified** - run and confirmed on Manan's Windows 11 (Omen) + iPhone.
- **Platform limitation** - the OS does not allow the full version; the limitation is named.

When the real-device pass is done, the merge to main follows [merge-checklist.md](merge-checklist.md).

Preview screenshots shown during development use synthetic data (mock apps, mock volumes) unless labeled otherwise. "Working" in milestone notes means automated-tested; it never means device-verified.

## End-to-end suite

Beyond the per-row unit/integration tests, an end-to-end suite (142 declared tests across 32 files) runs the real phone client core against the real desktop service over real pinned TLS on every push. It covers: QR pairing (single-use, tamper-proof, safe expiry), pinned-certificate identity (a lookalike desktop is never trusted), session renewal and token rotation, endpoint relocation after a desktop restart, multi-phone concurrency and queue-overflow honesty, device listing/scoping/revocation, clipboard sync (echo suppression, history paging/apply, stale-write conflict), file transfer (multi-chunk, resume-from-offset, cancel wiping partials, both directions), remote input (approval gate, ordered batching, macros, heartbeat release when the phone goes silent), terminal (approval gate, streamed output, one session at a time, Ctrl+C that really stops the command tree), browser tabs through the real loopback extension channel, automations (real-clock firing for app, scene and power actions, exactly once), dictation (clean text, silence, engine failure, mid-stream and mid-transcription cancel), memory, agent tasks (approvals, kill switch, audit, and answer-only requests served by the picked local model over its real Ollama wire contract with the agent runner never invoked, honest failure when the model is offline or unpicked - no fallback to the agent), and protocol limits and fuzz. All pass locally and in CI; the real-device column below remains the honest gate. A test count is a claim only where the workflow job log shows executed passes - a cancelled or timed-out job is never a pass. CI integrity note (2026-10-24): the phone-core job in the ci workflow timeout-cancelled on heads d951adb..b5a2032 (two dictation tests left their sessions running, so the suite child process never exited); those runs were wrongly reported as green and are corrected here. Fixed at b24962c; phone-core CI pass counts from that head's job log only.

## iOS clipboard background: what is actually possible

Verified against Apple's developer forums and OWASP's iOS pasteboard notes (mas.owasp.org/MASTG-KNOW-0083, October 2026):

- **Since iOS 9, only foreground apps can access the pasteboard.** An app suspended in the background cannot read or react to the clipboard. Always-on clipboard sync in the background is not possible on stock iOS.
- **Since iOS 16, reading the clipboard without a user gesture shows a paste confirmation prompt.** Our phone->PC auto-detect while Orbit is open counts as programmatic access. Manan can silence it: Settings -> Apps -> Orbit -> Paste from Other Apps -> Allow (iOS 16.1+).
- **PC -> phone writes need no prompt**, but only while Orbit is running in the foreground; iOS suspends the app seconds after leaving it and the connection drops.
- The only near-background path would be APNs silent push waking the app briefly - that needs a push server and is not built. Not promised.
